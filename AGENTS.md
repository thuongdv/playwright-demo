# AGENTS.md — Playwright Automation & Agentic Operating Guidelines

This document provides architectural context, strict operational conventions, skill workflows, and CLI commands for AI agents operating in this repository.

---

## 🧭 Repository Overview & Architecture

This repository is an enterprise-grade **Playwright + TypeScript** test automation framework. It implements a **Deterministic Two-Stage Pipeline** that decouples DOM element discovery from test authoring:

```text
               Stage 1: Harvester Pipeline (Deterministic Playwright, No LLM)
  AUT Deploy ──────────────────────────────────────────────────────────► .agents/page-map/*.json
                                                                                │
                                                                                ▼
                                                                     npm run codegen:pom
                                                                                │
                                                                                ▼
                                                                     src/pages/*/generated/*.ts
                                                                                │
               Stage 2: Browser-Free Test Authoring                             │
  tests-md/*.md ───────────────────────────────────────────────────────► src/tests/ui/*.spec.ts
```

### Key Highlights

- **Zero Browser Launch for Authoring**: AI agents author tests using offline JSON Page Maps and generated Page Object Models (POMs) without spinning up browsers to explore the DOM.
- **Deterministic & Secret-Safe**: Harvesters produce zero git diff on unchanged applications. Tokens, dates, nonces, and IDs are normalized (`<DATE>`, `<ID>`, `<CURRENCY>`, `<UUID>`), and sensitive data is stripped by the secret sanitizer pass.
- **Multi-Role Authentication**: Built-in `AuthManager` with cached session storage state (`.auth/<role>.json`).
- **Multi-Project Playwright Setup**: Supports multiple test projects (e.g. `ui-hotel`, `ui-ta`).

## ⚡ Standard Agent Workflows

### 1. End-to-End Test Delivery Lifecycle

When requested to deliver or implement a test from a spec (e.g. `tests-md/RESERVE_010.md`):

1. **Examine the Spec**: Read `tests-md/<TEST_ID>.md` to identify required routes, user roles, input data, and expected outcomes.
2. **Check Targets & Page Maps**:
   - Inspect `.agents/harvester/targets.ts` and `.agents/page-map/`.
   - If routes/pages are missing, add/update target entries in `.agents/harvester/targets.ts`.
3. **Harvest & Generate POMs**:
   ```bash
   npm run harvest
   # Or single target: npx tsx .agents/harvester/run.ts --config .agents/harvester/targets.ts --only <PageKey>
   npm run codegen:pom
   ```
4. **Author Test Spec (Browser-Free)**:
   - Read `.agents/page-map/<PageKey>.index.json` and `<PageKey>.<role>.<variant>.json` to locate element keys.
   - Use POMs in `src/pages/<area>/` and fixtures from `src/fixtures/base-fixture`.
   - Create `src/tests/ui/<area>/<TEST_ID>.spec.ts`.
5. **Static Quality Verification**:
   ```bash
   npm run format
   npm run lint
   npm run tsc
   npm run lint:check
   npm run format:check
   ```
6. **Targeted Test Execution**:
   ```bash
   # Run only the delivered test
   npm run test:ui-hotel -- -g "<TEST_ID>"
   # or
   npm run test:ui-ta -- -g "<TEST_ID>"
   ```

## 📏 Coding Standards & Best Practices

### 1. Locator Strategy

- **Accessibility-First**: Always prefer user-facing locators (`getByRole`, `getByLabel`, `getByPlaceholder`, `getByText`, `getByTestId`).
- **Never Use Brittle Selectors**: Avoid raw XPath or fragile CSS chains like `div > div:nth-child(2) > span`.
- **Field Suffix Naming**:
  - `Text` for input/textarea (e.g. `usernameText`, `emailText`)
  - `Button` for button/link triggers (e.g. `submitButton`, `loginButton`)
  - `Checkbox` for checkboxes (e.g. `agreeCheckbox`)
  - `RadioButton` for radio inputs (e.g. `genderRadioButton`)
  - `Dropdown` for `<select>` or custom select menus (e.g. `countryDropdown`)
  - `Label` / `TextLabel` for static text, headers, and descriptions (e.g. `titleLabel`)
  - `Area` for cards, sections, or container groups (e.g. `productArea`)

### 2. Assertions & Timing

- **Web-First Assertions**: Always use auto-retrying assertions (`await expect(locator).toBeVisible()`, `await expect(locator).toHaveText(...)`, `await expect(locator).toBeEnabled()`).
- **No Hardcoded Sleeps**: NEVER use `page.waitForTimeout()` or `setTimeout`. Wait on states, locators, or network responses instead.
- **Test Isolation**: Each test must be completely independent. Clean up state or use unique data per test.

### 3. Stuck Protocol & Issue Tracking

If a test fails or becomes flaky:

- Attempt targeted fixes (locator adjustment, auto-retry wait, fixture inspection) up to 2–3 times.
- If blocked by environment, third-party instability, or application defect, record the issue in [`.agents/knowledge/blockers.md`](.agents/knowledge/blockers.md) with:
  - Timestamp & title
  - Description of blocker
  - Resolution or current workaround status
  - Relevant logs / trace info

## 🛠️ Essential CLI Command Reference

### Compilation, Linting & Formatting

```bash
# Type check without emitting JS
npm run tsc

# Run linter and autofix
npm run lint

# Check linting rules
npm run lint:check

# Format codebase with Prettier
npm run format

# Verify formatting
npm run format:check
```

### Harvester & Codegen

```bash
# Harvest all configured targets
npm run harvest

# Harvest a single target page
npx tsx .agents/harvester/run.ts --config .agents/harvester/targets.ts --only <PageKey>

# Harvester dry-run (validate routes & DOM without saving to disk)
npx tsx .agents/harvester/run.ts --config .agents/harvester/targets.ts --dry-run

# Generate typed POM classes from page maps
npm run codegen:pom
```

### Test Execution & Reporting

```bash
# Run all tests
npx playwright test

# Run Hotel suite
npm run test:ui-hotel

# Run TestArchitect suite
npm run test:ui-ta

# Run a specific test by title / tag
npx playwright test -g "<TEST_ID>"

# Run tests in headed browser mode
npx playwright test --headed

# Open HTML test report
npm run report
```
